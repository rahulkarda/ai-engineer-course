## Exercise 1: Multi-Stage Dockerfile for FastAPI

```dockerfile
# ─── Stage 1: Builder ────────────────────────────────────────────────────────
FROM python:3.12-slim AS builder

WORKDIR /build

# Install build dependencies only in the builder stage
RUN apt-get update && apt-get install -y --no-install-recommends \
        gcc \
        libpq-dev \
    && rm -rf /var/lib/apt/lists/*

# Copy dependency files first — changes here bust cache but not source changes
COPY pyproject.toml ./
COPY requirements.txt ./          # or generated by: pip-compile pyproject.toml

# Install into an isolated prefix so we can copy only the wheels/site-packages
RUN pip install --upgrade pip \
 && pip install --prefix=/install --no-cache-dir -r requirements.txt


# ─── Stage 2: Runtime ────────────────────────────────────────────────────────
FROM python:3.12-slim AS runtime

# Security: create and switch to a non-root user
RUN groupadd --system appgroup \
 && useradd  --system --gid appgroup --no-create-home nonroot

WORKDIR /app

# Copy installed packages from builder — no build toolchain in the final image
COPY --from=builder /install /usr/local

# Copy application source
COPY src/ ./src/

# Ownership to nonroot before switching
RUN chown -R nonroot:appgroup /app

USER nonroot

EXPOSE 8000

# Use exec form so signals reach uvicorn (not a shell wrapper)
CMD ["uvicorn", "src.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### Why Multi-Stage?

| Layer | Builder stage | Runtime stage |
|---|---|---|
| gcc, libpq headers | Yes | No |
| pip cache | Discarded | Not present |
| Test/dev deps | Optional install | Never copied |
| Final image size | ~600 MB | ~120 MB |

The `--prefix=/install` trick copies the entire installed package tree as a single
`COPY --from=builder` layer. Only what the app needs at runtime ends up in the image.

## Exercise 2: docker-compose.yml

```yaml
# docker-compose.yml
version: "3.9"

services:
  web:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "${APP_PORT:-8000}:8000"
    environment:
      DATABASE_URL: ${DATABASE_URL}
      SECRET_KEY:   ${SECRET_KEY}
      REDIS_URL:    ${REDIS_URL}
      LOG_LEVEL:    ${LOG_LEVEL:-info}
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    volumes:
      - postgres_data:/var/lib/postgresql/data
    environment:
      POSTGRES_DB:       ${POSTGRES_DB}
      POSTGRES_USER:     ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    command: redis-server --save 60 1 --loglevel warning
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 3s
      retries: 5
    restart: unless-stopped

volumes:
  postgres_data:
  redis_data:
```

### Key Points

- **`condition: service_healthy`** — `web` starts only after DB and Redis pass their
  healthchecks, not just after the container starts (which is what `depends_on: [db]` alone does).
- **Named volumes** — data survives `docker compose down`; removed only with `docker compose down -v`.
- **No secrets in compose file** — every value comes from `${VAR}` expansion at runtime.

## Exercise 3: .env.example

```bash
# .env.example — copy to .env and fill in real values
# NEVER commit .env to source control

# ── Application ───────────────────────────────────────────────────────────────
APP_PORT=8000           # Host port to bind (container always uses 8000)
LOG_LEVEL=info          # uvicorn / Python logging level: debug|info|warning|error

# ── Security ──────────────────────────────────────────────────────────────────
SECRET_KEY=             # Long random string — generate: openssl rand -hex 32

# ── Database ──────────────────────────────────────────────────────────────────
POSTGRES_DB=            # Database name, e.g. myapp
POSTGRES_USER=          # Postgres username
POSTGRES_PASSWORD=      # Strong password — never use 'password' or 'postgres'
DATABASE_URL=           # Full DSN: postgresql+asyncpg://<user>:<pass>@db:5432/<db>

# ── Redis ─────────────────────────────────────────────────────────────────────
REDIS_URL=              # redis://redis:6379/0  (service name 'redis', db index 0)
```

### How the App Reads These Values

```python
# src/config.py
import os
from pydantic_settings import BaseSettings
from pydantic import PostgresDsn, RedisDsn


class Settings(BaseSettings):
    """
    pydantic-settings reads from environment variables automatically.
    Validation happens at import time — missing required vars raise immediately.
    """
    database_url: PostgresDsn
    secret_key: str
    redis_url: RedisDsn
    log_level: str = "info"

    class Config:
        env_file = ".env"           # only loaded when not already in environment
        env_file_encoding = "utf-8"


settings = Settings()
```

**Never use `os.getenv("SECRET_KEY")` scattered across the codebase** — centralise in
`Settings` so misconfiguration is caught at startup, not at the first request that uses it.

## Exercise 4: Adding Redis to docker-compose (already included above)

The Redis service is already present in Exercise 2's `docker-compose.yml`. Here is how
FastAPI connects to it using the environment variable:

```python
# src/cache.py
import logging
import os

import redis.asyncio as aioredis

logger = logging.getLogger(__name__)

_redis_client: aioredis.Redis | None = None


async def get_redis() -> aioredis.Redis:
    """
    FastAPI dependency. Returns a shared Redis client.
    URL comes exclusively from the environment — no hardcoded defaults.
    """
    global _redis_client
    if _redis_client is None:
        redis_url = os.getenv("REDIS_URL")
        if not redis_url:
            raise RuntimeError("REDIS_URL environment variable is not set")
        _redis_client = aioredis.from_url(
            redis_url,
            encoding="utf-8",
            decode_responses=True,
        )
        logger.info("Redis client initialised at %s", redis_url)
    return _redis_client


async def close_redis() -> None:
    """Call from FastAPI lifespan shutdown."""
    global _redis_client
    if _redis_client:
        await _redis_client.aclose()
        _redis_client = None
        logger.info("Redis client closed")
```

```python
# src/main.py  (lifespan + route example)
from contextlib import asynccontextmanager
import logging

from fastapi import Depends, FastAPI

from src.cache import close_redis, get_redis

logger = logging.getLogger(__name__)


@asynccontextmanager
async def lifespan(app: FastAPI):
    logger.info("startup complete")
    yield
    await close_redis()
    logger.info("shutdown complete")


app = FastAPI(lifespan=lifespan)


@app.get("/cache/{key}")
async def read_cache(key: str, redis=Depends(get_redis)):
    value = await redis.get(key)
    return {"key": key, "value": value}
```

### Why Each Entry Matters

| Entry | Reason |
|---|---|
| `.git` | Large, leaks repo history into image, breaks layer cache on every commit |
| `.env` | Contains secrets — must never enter the image or any registry |
| `__pycache__ / *.pyc` | Stale bytecode causes subtle bugs; Python recompiles from source |
| `.pytest_cache` | Test artefacts; unneeded at runtime |
| `dist / *.egg-info` | Old build outputs; could shadow freshly installed packages |
| `node_modules` | Typically hundreds of MB; never needed in a Python image |
| `.venv` | Local virtualenv; image has its own installed packages from builder stage |
