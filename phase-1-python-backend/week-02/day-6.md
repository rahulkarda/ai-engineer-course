## Exercise 0 — Setup: generate sample data

Write `generate_transactions(n: int, seed: int = 42) -> list[dict]` that produces `n` synthetic transactions. Each transaction must have:

| Field | Type | Notes |
|-------|------|-------|
| `id` | `str` | `"TXN-{i:06d}"`, some deliberately duplicated |
| `amount` | `float` | Random 1–10000, rounded to 2 dp |
| `status` | `str` | One of `"success"`, `"failed"`, `"pending"`, `"refunded"` |
| `category` | `str` | One of `"retail"`, `"wholesale"`, `"internal"` |
| `currency` | `str` | `"USD"`, `"EUR"`, or `"GBP"` |
| `created_at` | `str` | ISO-8601, spread over 30 days |

Requirements:
- Use Python's `random.Random(seed)` for reproducibility.
- Introduce ~10% duplicate IDs (re-use an earlier ID with a different amount).
- Save to `data/transactions.json`.

## Exercise 1 — Data loading and validation (45 min)

Build `load_and_validate(path: Path) -> tuple[list[dict], list[str]]`:

- Load JSON from `path`.
- Validate every row: all six fields present, correct types, `amount > 0`, `status` in allowed set, valid ISO date string.
- Return `(valid_transactions, list_of_error_strings)`.
- Each error string must include the row index and a human-readable description.

Write at least **three pytest tests**:
- All-valid file returns empty error list.
- File with three invalid rows returns exactly three errors.
- File not found raises `FileProcessingError` (your custom exception from day 5).

## Exercise 2 — Aggregation and grouping (60 min)

Implement these five pure functions (no external libraries):

```python
def total_successful(transactions: list[dict]) -> float:
    """Sum of amounts for status == 'success'."""

def find_failed(transactions: list[dict]) -> list[dict]:
    """All transactions with status == 'failed', sorted by amount desc."""

def group_by_status(transactions: list[dict]) -> dict[str, list[dict]]:
    """Dict mapping each status to its list of transactions."""

def group_by_category(transactions: list[dict]) -> dict[str, list[dict]]:
    """Dict mapping each category to its list of transactions."""

def currency_totals(transactions: list[dict]) -> dict[str, float]:
    """Sum of amounts per currency, rounded to 2 dp."""
```

Requirements for each:
- Type-annotated.
- Works on empty input without error.
- Covered by at least one pytest test with a meaningful assertion (not just "runs").

## Exercise 3 — Duplicate detection (45 min)

Implement:

```python
def find_duplicate_ids(transactions: list[dict]) -> dict[str, list[dict]]:
    """
    Return a dict where keys are IDs that appear more than once,
    and values are all transactions with that ID.
    """
```

Then write `remove_duplicates(transactions: list[dict]) -> list[dict]` that keeps the **highest-amount** occurrence for each duplicate ID. For equal amounts, keep the **first** occurrence (rely on sort stability).

Write tests that:
- Confirm no duplicates remain in output.
- Confirm the kept record is the highest-amount one.
- Handle the edge case where all records are unique.

## Exercise 4 — Sorting pipeline (45 min)

Implement:

```python
def sort_by_amount(
    transactions: list[dict],
    *,
    descending: bool = True,
    status_filter: str | None = None,
) -> list[dict]:
    """
    Return transactions sorted by amount.
    If status_filter is given, only include matching transactions.
    keyword-only arguments required.
    """

def top_n_per_status(transactions: list[dict], n: int) -> dict[str, list[dict]]:
    """
    For each status, return the top-n transactions by amount.
    """
```

Requirements:
- `sort_by_amount` uses a lambda key.
- `top_n_per_status` uses `group_by_status` (from Exercise 2) + sorting + slicing.
- Write tests verifying order is correct for both ascending and descending.

## Exercise 5 — Full pipeline + JSON round-trip (45 min)

Assemble a `run_pipeline(input_path: Path, output_path: Path) -> dict` function that:

1. Loads and validates (Exercise 1) — skips invalid rows with a warning log.
2. Runs all aggregations (Exercise 2).
3. Finds and resolves duplicates (Exercise 3) — keeps highest-amount per ID.
4. Sorts the clean data by amount descending (Exercise 4).
5. Writes the clean data back to `output_path` as JSON (Exercise 5 new: use `json.dump` with `indent=2`).
6. Returns a summary dict:

```python
{
    "input_count": int,
    "invalid_count": int,
    "duplicate_ids": list[str],
    "output_count": int,
    "total_successful": float,
    "currency_totals": dict[str, float],
    "status_breakdown": dict[str, int],   # count per status
}
```

Write an **integration test** that:
- Generates 100 transactions via Exercise 0.
- Runs the pipeline.
- Asserts `output_count <= input_count`.
- Asserts no duplicate IDs in the output file.
- Asserts summary totals match re-computed aggregates.
