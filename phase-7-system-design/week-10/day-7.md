# Phase 7 · Week 10 · Day 7 (Sunday) — Project Completion + Self-Assessment

> Objective: Finalize the week project deliverables and complete the week assessment.  ·  Time: ~3 hr project + 1 hr assessment  ·  Prereqs: [[week-10/day-6]]

## Overview

Today has two tasks:

1. **3 hours** — Finalize your project: story bank, design doc, and five written behavioral responses. See `project.md` for the full specification.
2. **1 hour** — Complete the assessment: `assessment.md`. The assessment is scored independently; treat it as a simulated interview session.

---

## Project finalization checklist

Before submitting your project, verify each deliverable:

### Story bank (8–10 STAR entries)

- [ ] 8–10 entries, each with all four STAR elements present
- [ ] At least one story per competency area (8 competencies, 8 stories minimum)
- [ ] Every result section contains one quantified outcome
- [ ] Every result section contains one learning or reflection sentence
- [ ] Stories are "I"-framed, not "we"-framed
- [ ] At least one failure story with full ownership
- [ ] Each story has a dual-use reframe line for at least one secondary competency
- [ ] No story requires more than 2 minutes to tell (test this: read it aloud, time it)

### One-page design doc

- [ ] All seven sections present (title/metadata, problem, goals, non-goals, proposed solution, alternatives, open questions, success metrics)
- [ ] Problem section includes quantified cost of inaction
- [ ] Goals are measurable (each has a testable criterion)
- [ ] Non-goals explicitly exclude at least 2 in-scope-looking items
- [ ] At least 2 alternatives considered, each with a rejection reason
- [ ] Open questions have named owners and resolution dates

### Five written behavioral responses

These are 5 responses written in full, to the following prompts (see `project.md` for the full list):
1. A time you made a decision with incomplete information.
2. A time you disagreed with a technical direction and how you handled it.
3. A failure or mistake you are proud of recovering from.
4. A time you had to communicate a complex technical topic to a non-technical audience.
5. A time you mentored or grew someone on your team.

Each response should be:
- Full STAR format
- 200–350 words written
- Include a quantified result
- Include a reflection/learning sentence

## Reflection exercise

Before taking the assessment, spend 15 minutes on these self-reflection prompts. Write your answers privately — they are for your own calibration, not graded.

**1. Competency confidence map**

Rate yourself on each competency 1–5 (1 = weak story, 5 = strong with a recent, quantified example):

| Impact / results | | |
| Ambiguity | | |
| Collaboration | | |
| Mentoring | | |
| Technical communication | | |

**2. Story bank gaps**

Which competency has your weakest story? What would need to happen in the next 6 months for you to have a better story for it?

**3. Design doc self-assessment**

In your design doc, what was the hardest section to write and why? What does that reveal about the decision you documented?

**4. Communication range**

Think about the last technical decision you communicated at work. Did you naturally adapt the message for different audiences? What would you change if you sent it again today?
